# SGI O2 (IP32)

The O2 is SGI's unified-memory workstation: CRIME (the memory controller and
rendering engine), MACE (the I/O chip: PCI, Ethernet, serial ports, PS/2,
audio, the clocks) and GBE (the display engine, which scans the frame buffer
out of main memory). IRIS emulates it with an R5000, R10000 or R12000, chosen at
run time like the other machines.

It runs IRIX 6.5 (tested with 6.5.22) to the desktop, with networking, audio,
SCSI disks and CD-ROMs, X and OpenGL through the CRIME rendering engine, and
NetBSD 11 to multi-user and X (its `crime` driver, accelerated). OpenBSD 6.9
boots but is not maintained. Linux is not usable yet.

iris-gui runs the O2 too: choose "SGI O2 (IP32)" as the platform. It has no
embedded PROM, so have an IP32 image ready.

## Configure the machine

An O2 is set up with the same keys as the other machines; `[o2]` holds only
what the O2 alone has (`mouse`, `control_port`, `arcs_fpu`).

```toml
prom  = "ip32prom.rev4.18.bin"   # the O2 PROM (not built in); tried when prom is left unset
nvram = "flash.bin"              # the PROM's flash, where setenv settings live
banks = [256, 256, 256, 256]     # the kit in each DIMM pair, largest first: 1 GB
serial_port_a = 2291             # first serial port (the console when headless)
serial_log = "serial.log"

[machine]
profile = "o2_ip32"
cpu = "r10000"              # or "r5000" or "r12000"

[o2]
control_port = 2293

[[port_forward]]
proto = "tcp"
host_port = 2292
guest_port = 22

[scsi.1]
path = "irix6522.raw"

[scsi.4]
path  = "irix6522.iso"
cdrom = true
```

Paths are relative to the directory iris runs in. Every key is listed in
[FEATURES.md](../FEATURES.md), the O2's own under [`[o2]`](../FEATURES.md#o2).

The PROM image is not built in: supply the O2 PROM (4.18 is the last
release) as `prom`; when `prom` is left at its default, iris tries
`ip32prom.rev4.18.bin`. Two forms of the image load:

- the raw 512 KiB flash, such as `ip32prom.rev4.18.bin` and
  `ip32prom.rev4.3.bin`;
- the installer's `ip32prom.image` (`usr/cpu/firmware/` in the IRIX 6.5.30
  installer). It is 431,872 bytes: a 256-byte header
  (`PROM`, then the payload length at +12) and 431,616 bytes of flash. iris
  strips the header when the length field matches the file and fills the rest
  of the 512 KiB part with erased (0xff) bytes.

The payload of the 6.5.30 image equals the 4.18 flash except in the
environment section, where the 4.18 file carries a stock environment
(`console=g`, `volume=80`, a network address, ...) and a checksum and the
6.5.30 image has it blank. Started from a blank flash, the PROM writes the
same defaults into it itself, which `nvram` keeps, and both images play the
same boot chime sample for sample.
A file that is neither form (a wrong size, or a header whose length does not
match the file) is refused at start with the reason. The O2 has no NVRAM chip; the PROM keeps its
environment (`setenv`) in flash, and `nvram` names the file that flash is
kept in between runs (`nvram.bin` unless set): IRIS starts from it when it
exists and saves the flash back whenever the guest writes it, so settings
survive a restart. The PROM image itself is never written.

Configs from before this layout set all of it in `[o2]` (`prom`, `flash`,
`ram_mb`, `dimms`, `disks`, `serial_port`, `serial_log`, `graphics`,
`cpu_mhz`, `net`, `forwards`). They still load: iris moves each onto the
shared key it stands for, says so once, and never writes them back. Move them
in the file to silence the note.

## CPU, memory and clock

- **R5000, R10000 and R12000** all run the shadow cache model that IP28 uses, from
  reset: loads and stores go straight to memory. The PROM tests physical page
  0 uncached while its stack sits in cache tags for that same page, so while
  those tags stand the bus answers for the page from a separate 4 KB page.
- Linux supports only R5000-class O2s.
- `[clock] fixed_mhz` is CP0 Count, half the part's clock unless set (90 MHz for
  the R5000); the PROM measures and reports twice it as the CPU clock. `r10000`
  is the rev 3.4 250 MHz part and `r12000` the rev 3.5 400 MHz part with a 2 MB
  secondary cache. Both have 64-byte secondary lines, because the PROM fails with
  128-byte ones.
- `banks` is the kit in each of the four DIMM pairs from A: 32, 64, 128 or
  256 MB each, largest first, up to 1 GB. The default `[128, 128]` is 256 MB.
  IRIX boots with any of them, from a single 32 MB kit up. NetBSD's 32-bit
  kernel uses only the first 256 MB, however much is fitted.

## Disks and CD-ROMs

The `[scsi.N]` tables ([FEATURES.md](../FEATURES.md#scsiid)) list the devices
on the two Adaptec 7880 controllers. `N` 1–7 is the id on the internal bus
(controller 0); `N` = 16 + id is that id on the external bus (controller 1),
so `[scsi.17]` is id 1 outside and both buses can carry an id 1. `controller
= 1` in a low-numbered table means the same. IRIX expects the system disk at
id 1 on bus 0 and looks at ids 1 to 4 on the internal bus. In the monitor,
`scsi` and `cow` address controller 0 and `scsi1` and `cow1` controller 1
([debug.md](../debug.md#scsi-cd-rom-and-disks)). Everything the
tables offer elsewhere works here: raw and CHD images, `cdrom = true` with a
`discs` changer list (RCtrl+F12 in the window, `iris-ci cdrom-eject`),
`overlay = true` for copy-on-write to `PATH.overlay` (delete it to start
over), and a `scratch = true` volume for the CI socket's file injection
([STORAGE.md](../STORAGE.md)). The one exception is `kind = "daynaport"`: the
O2's Ethernet is built in. The `--scsi1`, `--cdrom4` and related command-line
options apply as well. An image that cannot be opened stops iris before the
PROM runs, as on the other machines.

The PCI bus, its wiring and reset are described in [docs/pci.md](pci.md).

The controllers themselves are Adaptec AIC-7880s. [docs/dev/aic7880.md](dev/aic7880.md)
describes the chip: how it works, its PCI configuration space, every
register, the sequencer and the programs the PROM, IRIX and the BSDs download
into it, and how the O2 wires it up.

Older configs listed the disks as `o2.disks = [ { id, path, cdrom, bus,
overlay } ]`. That key is deprecated: iris folds it into `[scsi.N]` (with
`controller = bus`) when it loads the file and says so; move the entries over
to silence the note.

## Snapshots

The monitor's `save NAME` and `load NAME`, and iris-ci's `save` and
`restore`, keep the O2 in `saves/NAME/` as they do the other machines: the
CPU, every device, all of memory (in the chunk store the snapshots share, so
memory that did not change costs nothing), the flash, and the changes on
`overlay` disks. A snapshot loads only into an O2 with the same CPU, memory,
disks and build. Use `overlay` disks for snapshots you mean to go back to: a
disk written in place keeps changing after the save, and the saved memory
will not match it.

## Console, keyboard and mouse

With the graphics console (the default) the PROM and IRIX use a PS/2
keyboard, and `[o2] mouse` (default on) adds a PS/2 mouse. With
`headless = true` there is no keyboard, and the console is serial port 1.
The graphics hardware is still there, as on a real O2 booted without a
keyboard: only the console changes.

`serial_port_a` and `serial_port_b` serve the two serial ports on TCP
127.0.0.1 (8880 and 8881 unless set; `telnet 127.0.0.1 PORT`); `serial_log`
copies everything the first one sends to a file.

## Networking

The O2's Ethernet is on IRIS's NAT gateway, as on the other machines, and
takes the same settings: `nat_subnet`, `[nfs]`, `[[port_forward]]`,
`[network] mac` (the address in the 1-Wire ID chip) and `tftp_dir`. The
guest gets 192.168.0.2 by DHCP, with the gateway and DNS at 192.168.0.1.
`[network] mode = "off"` leaves the Ethernet unplugged; `pcap` bridges it
onto a host interface instead, with no NAT services. `mode = "stream"` with
`stream = "tcp:IP:PORT"` or `"unix:PATH"` puts it on a private segment served
by another program. Both are described in [NETWORKING.md](../NETWORKING.md).

For a PROM network boot, set `[network] tftp_dir = "DIR"` and boot from the
PROM's command monitor with `boot -f bootp():FILE`, which loads FILE from DIR.

## Scripting and inspection

The monitor (`monitor_port`) has the O2's device commands (`crime`, `gbe`,
`re`, `mec`, `pci`, `audio`, ...) and an `o2 <command>` family; see
[debug.md](../debug.md#sgi-o2-ip32). `control_port` serves the same `o2`
commands on their own TCP port, one command per line, for scripts: screen
shots, typed text and keys, mouse motion and clicks, memory reads.

The rendering engine runs on its own thread (`CRIME-RE`) behind a deep interface
buffer, so the CPU keeps running while it draws. In a build with `gputrace`,
`re trace FILE` writes an annotated trace of the engine, GBE and CRIME, and
`re rec FILE` records the engine's writes for replay. A headless O2 has no
keyboard, so the PROM and IRIX take the serial console and no desktop starts.

The monitor's machine commands work as on the other machines:
`machine-stop`, `machine-start` and `reset` (the CPU is left stopped;
`machine-start` runs it). So does `gdb_port`.

`iris --ci` starts the O2 for [iris-ci](../STORAGE.md) with its CPU stopped
and serial port 1 as the CI console: `iris-ci start`, `serial-send`,
`serial-wait`, `login`, `run` and `screenshot` work as on the other
machines, and so do `save`, `restore`, the scratch volume and CD changes.
`rollback` does not yet; it answers "not supported on this machine". Boot
with `headless = true` so the PROM and the operating system use that
console.

## Known limitations

- Over iris-ci, no `rollback`.
- The PROM cannot load a very large program from disk (it fails on a 16 MB
  kernel); boot such a file over TFTP instead.
- MACE's two bus-master views of memory are both delivered in address
  order; the native view's word-preserving swap is handled per driver inside
  the SCSI model instead ([docs/dev/aic7880.md](dev/aic7880.md), section 3.3).
