# The R10000 family — expectations from the manuals

The R10000, R12000 and R14000 (PRId implementation 0x09, 0x0E, 0x0F) are one
`CPU_R10000` kind: they share the R10000 User's Manual's programming model, and
`is_r12000_up()` separates the few places the later parts differ. **None has run
this suite.** No Indy ever carried one; iris runs them on the same Indy-shaped
bare machine as the other CPUs because, with the test device, it accepts any
CPU on any machine (`MachineConfig::cpu_part`). So every R10000 answer here comes
from a manual or, where the manuals stop, from iris itself, and this file says
which.

Sources, cited by printed page in the tests:

- **R10000 UM**: *MIPS R10000 Microprocessor User's Manual*, Version 2.0, SGI
  publication 007-2490-001.
- **NEC UM**: *VR10000 Series User's Manual*, NEC U10278EJ4V0UM, fourth edition.
  It covers the R12000 and lists what changed from the R10000 in Appendix B.
- Linux, `arch/mips/include/asm/cpu.h`, for the R12000 and R14000 PRId numbers.

No R14000 manual is cited. Every R14000 answer is assumed to equal the
R12000's, so wherever this file says a rule holds for the R12000, the R14000's
share of it is inferred.

## Where each expectation comes from

| class | tests | source |
|---|---|---|
| **Documented, differs from the R4400** | `identity/prid`, `identity/fir` (FPU imp 0x09 on the R10000), `identity/cache_geometry`, `cache/geometry` (32 KB two-way, 64-byte I and 32-byte D lines, fixed rather than in Config), `cache/set_conflict` (two ways), `identity/tlb_size`, `cp0/random_respects_wired`, `cp0/wired_resets_random`, `tlb/all_entries` (64 entries), `cp0/entryhi_fill_zero` (Fill is 61:44), `cp0/xcontext_ptebase` (PTEBase is 63:37), `excep/cop2_unusable` (Reserved Instruction with CU2 set), `fpu/cvt_out_of_range` and `fpu/cvt_infinity` (Unimplemented Operation, not Invalid, on the R10000 and R12000) | R10000 UM pp. 238, 245, 256, 259, 308, 357; NEC UM Appendix B.4, p. 350 |
| **Documented, R10000 only** | every `r10k/*` test: single results and conditional moves zeroing the upper word with FR set (for untaken moves, documented for the R10000 alone), FCSR.FS flushing RECIP and MADD results, CVT.L's 51-bit limit (asserted on the R10000 alone), undefined COP1 opcodes and formats, BC0x and RFE, refill vector selection by address, 44-bit XContext, duplicate TLB entries and Status.TS, unused PFN bits, FrameMask, Index tag ways, Cache Barrier, Status.CH | cited in each test |
| **Documented, same as the R4400** | the rest of the `CPU_ALL` tests with no CPU branch: integer ISA, exceptions, CP0 masks, TLB, umode, compares and the FS=0 denormal rules in `fpu/denorm_*` (an operand or result takes Unimplemented Operation, R10000 UM p. 309, NEC UM p. 349) | the architecture, and pages that say the R10000 matches the R4400 |
| **Derived from the model** | `r10k/cond_move_s_upper` on the R12000 and R14000 (the R10000 UM p. 313 says an untaken single conditional move zeroes the upper word; the NEC UM p. 279 calls it "undefined ..., even if no move occurs", and iris zeroes it on all three); `identity/fir` on the R12000 and R14000 (the NEC UM gives 0x09 and no other FPU value, which is not the same as saying the later parts report it); `fpu/cvt_out_of_range` and `fpu/cvt_infinity` on the R14000 (inferred from the R12000); `fpu/vec_cvt_from_l` (no trap converting a long past 2^53: R10000 UM p. 312 says only that a 51-bit long "no longer takes an Unimplemented Operation exception", nothing about larger ones); `r10k/cvt_l_limit`'s bounds (iris reads "only up to 51 bits" as the range [-2^51, 2^51), 51 bits of magnitude beside the sign, and applies it to ROUND.L, TRUNC.L, CEIL.L and FLOOR.L as well as CVT.L, which the manual does not name; the test uses CVT.L only and stays away from the edge); `fpu/denorm_result_fs1`, `fpu/underflow_enable_e` and the FS=1 half of `fpu/denorm_double` (the U and I bits on a flushed result, and what an enabled Underflow does with FS set: the manual says only "replaced with zero. No exception is flagged"); `fpu/qnan_operand` (its operand is a MIPS signalling NaN, and NEC UM B.4 says only that the R10000 traps on "a NaN" input); `mem/lwr_all_offsets` (MIPS IV allows a partial LWR either answer and no R10000 manual picks one); `identity/config_k0` (the manuals say K0 is loaded from the mode bits at reset, not whether software may change it) | iris, recorded so the first real run knows what it is confirming |
| **Reported, not asserted** | `r10k/fr0_single_odd_half` (what a single result does to the odd register of an FR=0 pair); CVT.L of 2^52 on the R12000 and R14000 | the manuals call it undefined, or say nothing |

## What iris does not do

The failures listed for these CPUs in [`expected-failures.txt`](../expected-failures.txt)
beyond the ones every CPU shares:

- `cache/hit_inv_discards` and `r10k/ch_bit`: iris runs the R10000 family on the
  shadow cache only (`CacheModel::is_shadow`), where memory is the only store
  and the tag arrays answer CACHE instructions without recording which lines
  loads and stores brought in. A Hit Invalidate has no dirty line to discard
  and a secondary Hit operation never hits.
